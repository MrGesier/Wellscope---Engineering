# Distributed loads feeding the string shape

## Engineering decision

The useful output is a depth-resolved load profile tied to the same survey, tally, mud and bit depth as the 3D shape, plus the locations where supplied equipment limits are exceeded. Use it to compare assumptions and identify missing ratings, not to certify an operating window.

The cached Drive white paper *Holistic Approach To Find Fit-for-purpose BHA Design* (DrillScan, 2019) discusses directional sensitivity to WOB, hole overgauge and bit steerability, and subsequent field validation. Those results are case-specific: no generic WOB-to-DLS law or rating is inferred here. Its lesson is to compare complete designs under declared conditions, not merely tool silhouettes.

Public primary references:
- [Rezvani and Techentien, AADE-05-NTCE-50](https://www.aade.org/download_file/2710/491): load prediction and component strength data for completion planning; distinguishes soft and stiff string approaches. This paper is context, not validation of our numerical implementation.
- [H&P, Stiff String Casing Design: Tortuosity and Centralisation, SPE207935](https://www.hpinc.com/resources/technical-paper/stiff-string-casing-design-tortuosity-and-centralisation): stiffness, clearance and centralization influence load/stress assessment. The present one-way approach does not implement that coupled formulation.

## Implemented model

`StringLoads.solve` adapts the current string input to the existing documented `RunMechanics` soft-string model (see DISTRIBUTED_RUN.md). It regenerates effective force F(MD), wall force and transmitted torque from scratch after any study change. Stable component IDs are generated by tally index for this independent study. No external RunWorkspace result is silently reused.

Required `input.axial`: `mode: "soft-string"`, `source`, `stepM`, `muOpen`, `muCased`, `bottomForceN`, `bottomTorqueNm`, `axialSpeedMps`, `rpm`, `blockN`. Optional rigLimitN, driveLimitNm and limitSource use the same coverage rules as RunMechanics. Tool ratings remain on each component and are editable in the UI. SI values in JSON; UI forces use tf and torques tf.m (1 tf = 9806.65 N).

Only a cased prefix followed by open hole is supported; reversed/multiple alternations are rejected, not approximated with one shoe. Both fluid densities equal input.rho, surface pressures are zero. Hydrostatic wall-force corrections use the existing RunMechanics TVD interpolation. The transverse bore uses exact minimum-curvature arcs; axial rates retain RunMechanics midpoint inclination/azimuth interpolation. These discretizations are not a fully consistent stiff-string formulation.

The beam geometric-stiffness term on each edge uses the average effective tension, obtained by integrating the piecewise-linear axial profile across all overlapping axial cells. Wall force is NOT used for geometric stiffness. Axial integration spacing is independent of beam mesh spacing. The profile is passed one way into shape equilibrium; beam contact reactions never update drag or torque. Torque changes the transmitted-load checks, not the torsional deformation of the 3D string. Centered end pins remain imposed. Non-positive-definite systems are rejected, with no post-buckling shape invented.

## Reading the result

Depth increases downward on both force and torque plots. The local 3D cross-section reports effective tension at the inspected beam station. CSV exports MD, tally index, effective force, wall force and torque; full study JSON and frozen A/B preserve the settings and ratings. A/B geometry comparison requires identical axial boundary settings and integration step; component changes legitimately regenerate different profiles.

Known exceedances take precedence over incomplete coverage. Missing manufacturer/source/rig data remain explicit. Tube von Mises checks include axial wall stress, pressure and torsion but EXCLUDE BENDING. The displayed bending field is not included in that acceptance calculation. Compression requires a separate buckling assessment. No fatigue, wear, dynamic travel, motor RPM differential, friction calibration or field validation is claimed.

Playback direction must agree with the applied physical axial speed. Animation step is only display/depth sampling, not the physical speed. On failure/dirty input the shape and load charts are cleared; no stale result is presented as current.

## Verification

Analytic vertical buoyed weight and intermediate effective forces; integrated tension across axial cells; equivalence to constant-tension beam when the generated profile is constant; horizontal pickup/slackoff friction sign and magnitude; rotational drag; known-exceedance priority with missing ratings; unsupported architecture; immutable inputs; complete 3800 m equilibrium. Browser checks cover units, current-state invalidation, A/B mismatch, limits and direction gates. These are software/analytic tests, not validation against a matched field input deck.
